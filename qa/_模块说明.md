# 模块说明：qa —— 测试门禁脚本

| 项 | 内容 |
|---|---|
| 中文名 | 可复跑的测试门禁（QA） |
| 一句话 | 把"改完代码必须验证"落成脚本：算法层四门禁、从零构建、Python 层回归。只做校验，不改产品代码 |
| 跑在哪 | **PC 的 WSL Ubuntu 22.04**（gcc + make + Python3）；不需要硬件 |
| 谁改 | 门禁口径变化时改这里（例如新增一个检查项）；改门禁必须同步改 `README.md` 里的门禁表 |

## 脚本清单

| 脚本 | 作用 | 成功标志 |
|---|---|---|
| `run_core_tests.sh` | `firmware_core` 四门禁：`check-purity` + `lib` + `test` + `test-asan` | 全部 `PASSED` / `0 failures`，退出码 0 |
| `run_fresh_build.sh` | 从零构建（`git clean` 式重编）验证可复现 | `.so` 的 BuildID 与基线一致 / 编译 0 error |
| `run_py_tests.sh` | Python 层：协议回归 + 跨语言对拍 + 端到端 | 46 用例 / 153 断言 0 失败；e2e 21/21 |
| `run_q03_b01.sh` | 历史审查用例（B-01 雷达检查脚本） | 断言全过 |
| `run_q03_b02.sh` | 历史审查用例（fake_stm32 时序） | 断言全过 |
| `run_q04_syntax.sh` | A-02 固件语法检查（WSL gcc `-fsyntax-only`，两种宏模式） | 0 error / 0 warning |
| `run_q05_b03.sh` | 历史审查用例（B-03） | 断言全过 |

## 用法

```bash
bash qa/run_core_tests.sh     # 算法层
bash qa/run_py_tests.sh       # Python 层
```

历史原始日志在 `D:\dsh\工程设计\qa\evidence\`（日志不入 git）。

## 规则

- 失败与超差结果**不得删除或改写**，必须记录（证据可追溯）。
- 门禁脚本不要依赖硬件；需要硬件的检查要单独标注"现场执行"。
- 发现门禁本身写错，先修门禁再谈代码通过。
