# 模块说明：pi_setup —— 树莓派上机前脚本

| 项 | 内容 |
|---|---|
| 中文名 | 树莓派 5 上机前准备与自检脚本 |
| 一句话 | 真机联调前在树莓派上跑的一批脚本：串口权限、udev 规则、端口识别、算法 `.so` 安装、环境预检、雷达检查 |
| 跑在哪 | **树莓派 5**（`ssh yjc@omninav-pi.local`，等价 `192.168.137.50`），Ubuntu 24.04 + ROS2 Jazzy |
| 谁改 | 上机流程变化时改这里；算法/协议不要写进本目录 |

## 脚本清单

| 脚本 | 作用 |
|---|---|
| `preflight.sh` | 上机总预检：系统/内核/内存/磁盘、ROS 环境、Python 依赖、串口设备与权限、`/opt/omninav/lib` 是否就位 |
| `install_core.sh` | 把 `firmware_core` 编译出的 `libomninav_core.so` 安装到树莓派 `/opt/omninav/lib/`（供桥接 `ctypes` 加载） |
| `identify_ports.sh` | 识别 STM32 串口设备名与权限（`/dev/ttyUSB*`、`/dev/ttyACM*`），确认 `dialout` 组 |
| `check_lidar.sh` / `check_lidar.md` | 雷达只读检查：设备节点、波特率、能否出 `/scan`；不改任何系统配置 |
| `99-omninav-serial.rules` | udev 规则：把 STM32 与雷达的串口设备名固定下来 |
| `test_stm32_link.py` | 树莓派侧串口链路测试：发协议帧、看回帧，验证 STM32 ↔ Pi 通 |
| `shadow_probe.py` | 影子探测：在不影响主链路的前提下旁听串口数据 |

## 使用顺序（真机第一次）

```bash
ssh yjc@omninav-pi.local
sudo cp pi_setup/99-omninav-serial.rules /etc/udev/rules.d/ && sudo udevadm control --reload-rules
bash pi_setup/identify_ports.sh     # 看设备名/权限，确认用户在 dialout 组
bash pi_setup/preflight.sh          # 预检，逐项看 FAIL 项
bash pi_setup/install_core.sh       # 装 .so（需先把 firmware_core 拷上去并 make lib）
bash pi_setup/check_lidar.sh        # 雷达能否出数据
```

## 约束

- 这些脚本只做**只读检查 + 用户态安装**，不动内核参数、不装驱动、不刷固件。
- 树莓派 2 GB：不要在 Pi 上跑 Gazebo / rviz2 / Docker；仿真在 PC。
- 串口权限问题优先查 `dialout` 组与 udev 规则，不要用 `sudo` 跑 ROS 节点。
